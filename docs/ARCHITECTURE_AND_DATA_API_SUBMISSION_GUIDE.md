Open `architecture-diagram.svg` in a browser or image viewer. It is also included as an SVG asset suitable for a report or slide. The editable Mermaid source remains in `ARCHITECTURE.md`.

## Data source responsibilities

| Dataset | Purpose | Treatment / outcome | Important limitation |
|---|---|---|---|
| IBM Telco Customer Churn | Churn classifier, churn EDA, telecom segments | `Churn` target | Cross-sectional; no complaints log or longitudinal usage history |
| Hillstrom MineThatData Email Campaign | Randomized campaign uplift | Women's Email vs No Email; conversion outcome | Email conversion response is not telecom retention uplift |
| UCI Online Retail II | Customer-value forecasting, purchase trends, segmentation, survival proxy | Future 90-day revenue; purchase inactivity event | Revenue forecast is not calibrated lifetime value; inactivity is not confirmed cancellation |

Raw datasets are downloaded at runtime rather than redistributed in the project archive. Review each source's terms before redistributing downloaded data.

## API summary

Base URL in local Docker: `http://localhost:8000`. Interactive OpenAPI docs: `http://localhost:8000/docs`.

### `GET /health`

Checks whether the API process is responding. It does not prove database or model readiness unless the implementation explicitly checks those dependencies.

### `POST /predict/churn`

Accepts customer features such as `tenure_months`, `monthly_charges`, `total_charges`, `contract`, `internet_service`, `tech_support`, and `paperless_billing`. Returns a churn probability and a heuristic risk band. Missing optional features are handled by the trained preprocessing pipeline where supported.

### `POST /simulate/roi`

Accepts `eligible_customers`, `offer_cost_per_customer`, `incremental_lift`, and `contribution_value_per_save`. Returns total offer cost, expected incremental saves, incremental value, net benefit and ROI. `incremental_lift` is a scenario assumption unless it has been validated in a suitable experiment.

### `POST /simulate/uplift-roi`

Uses predicted Hillstrom uplift scores to estimate scenario economics for a selected target fraction and specified discount/contact costs. This is a campaign planning estimate, not a guaranteed profit outcome.

### `GET /customers/{customer_id}/survival`

Returns customer-specific retail purchase-inactivity survival estimates when a trained survival model and adequate baseline follow-up are available. The event is a 90-day inactivity proxy.

## Reproducible evaluation artifacts

After a successful full run, inspect:

- `artifacts/run_manifest.json` — dataset counts and scope notes
- `artifacts/telco_evaluation.json` — churn metrics and baseline comparison
- `artifacts/shap_status.json` and `artifacts/telco_shap_global.csv` — explanation status and feature contributions
- `artifacts/retail_clv_evaluation.json` — forward-revenue model and baseline metrics
- `artifacts/hillstrom_uplift_evaluation.json` — held-out uplift evaluation
- `artifacts/retail_km_median_survival.json` — survival metrics and diagnostics
- `artifacts/training_summary.json` — combined summary

These files are generated by training; no real-data metric should be claimed until the corresponding artifact exists and is inspected.
